# Правила проекта

## Основные принципы

### 1. Фреймворк bmad
- Все разработки ведутся с использованием фреймворка bmad
- При создании новых компонентов и функций следуйте паттернам bmad
- Используйте встроенные утилиты и библиотеки фреймворка

### 2. Язык разработки
- Основной язык разработки - **русский**
- Все комментарии в коде пишутся на русском языке
- Документация, README файлы и описания - на русском языке
- Переменные и названия функций на английском (стандарт)
- Commit messages и PR описания на русском

### 3. Git и коммиты
- Делайте коммиты **своевременно** - после завершения каждого логического блока работы
- Не копите изменения в одной большой работе
- Следуйте правилам:
  - Один коммит = одна логическая задача/исправление
  - Сообщения коммитов на русском языке, в повелительном наклонении
  - Формат: `[тип]: краткое описание`
    - `feat:` новая функциональность
    - `fix:` исправление ошибки
    - `refactor:` рефакторинг без изменения функциональности
    - `docs:` обновление документации
    - `test:` добавление/обновление тестов
    - `chore:` обслуживание проекта
- Проверяйте код перед коммитом (lint, typecheck)

### 4. Правила для MCP (Model Context Protocol)
- Используйте MCP агентов для сложных задач и многошаговых операций
- При работе с MCP:
  - Разбивайте сложные задачи на подзадачи
  - Проверяйте результаты работы агентов
  - Используйте специализированных агентов для специфических задач
- Запускайте специализированные агенты для:
  - Тестирования - `test-automator`
  - Код ревью - `code-reviewer`
  - Документации - `documentation-specialist`
  - Архитектуры - `architect-review`
  - И других специализированных задач

### 5. Структура проекта и деплой

#### Корневая директория проекта
```
/
├── Telegram Bot/          # Основной продукт и файлы для деплоя на VPS
│   ├── app/              # Исходный код приложения
│   ├── config/           # Конфигурационные файлы
│   ├── docker-compose.yml # Файл для docker-compose деплоя
│   ├── Dockerfile        # Docker образ приложения
│   ├── requirements.txt  # Зависимости Python
│   └── user-docs/        # Документация для пользователей
│
├── tests/                # Тесты проекта
│   ├── unit/            # Модульные тесты
│   ├── integration/     # Интеграционные тесты
│   └── e2e/             # End-to-end тесты
│
├── docs/                 # Документация для разработчиков
│   ├── architecture/    # Архитектура проекта
│   ├── api/             # API документация
│   ├── contributing.md  # Правила контрибьюции
│   └── development.md  # Гайд по разработке
│
├── AGENTS.md            # Этот файл с правилами проекта
├── README.md            # Описание проекта на русском
└── .gitignore           # Исключаемые файлы
```

#### Правила организации
- **Telegram Bot/** - только то, что нужно для деплоя на VPS
  - Docker конфигурации
  - Исходный код приложения
  - Конфигурационные файлы для продакшена
  - Документация для пользователей
  - Никаких временных файлов, тестов и dev-инструментов
  
- **tests/** - вся тестовая инфраструктура
  - Разделяйте на unit/integration/e2e
  - Используйте фикстуры и моки
  - Покрывайте критически важные части кода

- **docs/** - документация для разработчиков
  - Архитектурные решения
  - API документация
  - Гайды по разработке
  - Примеры использования

#### Чистота в рабочей директории
- Удаляйте временные файлы после работы
- Используйте .gitignore для исключения лишних файлов
- Не создавайте файлы в корне проекта без необходимости
- Следите за порядком в директориях, регулярно чистите от мусора

### 6. Разработка

#### Код стиль
- Следуйте PEP 8 для Python
- Используйте type hints (Python 3.12+)
- Пишите понятные имена переменных и функций
- Добавляйте docstrings на русском языке к функциям и классам
- Следите за количеством строк в файлах - оптимально до 600 строк
  - Разделяйте большие файлы на логические модули
  - Используйте принцип единственной ответственности
  - При превышении лимита рассмотрите рефакторинг

#### Тестирование
- Пишите тесты для новой функциональности
- Запускайте тесты перед коммитом
- Покрывайте бизнес-логику тестами

#### Документация
- Обновляйте документацию при изменениях
- Пишите README на русском языке
- Описывайте API и ключевые компоненты

### 7. Docker и деплой

#### Docker Compose
- Используйте docker-compose для деплоя на VPS
- Файл docker-compose.yml в папке "Telegram Bot"
- Определяйте все сервисы (app, db, redis и т.д.)
- Используйте .env файлы для конфигурации

#### Правила для Docker
- Dockerfile в папке "Telegram Bot"
- Используйте легкие базовые образы (alpine/slim)
- Минимизируйте слои
- Кэшируйте зависимости

### 8. Безопасность
- Не коммитьте секреты и ключи (.env, credentials.json и т.д.)
- Используйте переменные окружения для конфиденциальных данных
- Проверяйте зависимости на уязвимости
- Следуйте OWASP Best Practices

```bash
cd "Telegram Bot"

# Просмотр логов

```
